# 온바다 Android 작업 메모

이 문서는 SeaThermo Android 저장소의 현재 구현 상태와 검증 기준을 정리한 작업 메모다. Android 작업을 이어갈 때는 실제 코드와 이 문서를 함께 확인하고, 코드가 더 최신이면 코드를 우선한다.

## 앱 개요

온바다(SeaThermo)는 낚시 활동을 기록하고 해양 수온 데이터를 확인하는 Android 앱이다.

주요 기능:

- 현재/최신 해수 온도 확인
- 관측소 기반 현재수온 목록
- 내부 빌드 수온분석 화면
- GPS 기반 낚시 경로 기록
- 속도 기반 낚시 상태 분류: 이동중, 탐색중, 낚시중
- 조과 사진 저장 및 지도 마커 표시
- 세션별 낚시 히스토리 조회
- 지도 타입 선택
- 앱 버전 체크, 공지사항, 오픈소스 라이선스 화면

## 현재 구현 상태

### 공개/내부 빌드 분리

- Gradle flavor는 `public`, `internal` 두 가지다.
- 코드 분기는 `BuildConfig.INTERNAL_BUILD`를 기준으로 한다.
- 공개 앱 ID: `com.onbada.seathermo`
- 내부 앱 ID: `com.onbada.seathermo.internal`
- 현재 `versionCode`는 `5`, `versionName`은 `1.0.0`이다.
- Firebase 설정은 flavor별 파일을 사용한다.
  - `app/src/public/google-services.json`
  - `app/src/internal/google-services.json`
- 기존 루트 `app/google-services.json`은 public flavor 위치로 이동했다.

Android Studio에서는 `Build Variants`에서 다음 variant를 선택한다.

```text
publicDebug
internalDebug
publicRelease
internalRelease
```

### API와 기능 분기

공개 빌드:

- 현재수온은 공식 OpenAPI 기반 화면을 사용한다.
- 수온분석 탭은 준비중 화면을 표시한다.
- 앱 시작 시 `https://seathermo.com/api/regions`를 호출하지 않는다.
- crawling/직접 서버 호출 화면은 공개 빌드에 노출하지 않는다.

내부 빌드:

- 현재수온은 기존 crawling/직접 서버 호출 화면을 사용한다.
- 수온분석은 내부 분석 화면을 사용한다.
- 앱 시작 시 `/api/regions`를 호출해 관측소 목록을 캐시한다.

### 지도 설정

- 기본 지도 설정은 Google Map이다.
- Kakao 앱 키는 `local.properties`에서 flavor별로 주입한다.
  - `KAKAO_APP_KEY_PUBLIC`
  - `KAKAO_APP_KEY_INTERNAL`
  - 값이 없으면 `KAKAO_APP_KEY`를 fallback으로 사용한다.

## 내부 수온분석 상세 그래프

내부 빌드의 수온분석 상세 화면은 최근 7일 그래프 기준을 전환할 수 있다.

선택 기준:

```text
날짜별
12시간
6시간
3시간
```

동작:

- 기본 선택값은 `날짜별`이다.
- `"최근 7일 수온 변화"` 오른쪽에 Android 표준 드롭다운을 표시한다.
- 선택 기준에 따라 subtitle을 변경한다.
- 7일 수온 데이터는 30분 단위 샘플을 그대로 사용한다.
- 기준 변경은 데이터를 다시 호출하거나 라인을 다운샘플링하지 않는다.
- 선택 기준은 x축 세로선과 하단 라벨 tick 간격만 바꾼다.
- 날짜별은 카드 폭 안에서 표시하고 가로 스크롤하지 않는다.
- 12/6/3시간 기준은 그래프 영역만 가로 스크롤한다.
- 시간별 기준을 선택하면 스크롤 위치는 왼쪽 시작점이다.
- y축 온도 라벨은 왼쪽에 고정된다.

x축 라벨:

- 날짜별은 날짜만 표시한다. 예: `6/2`
- 시간별은 `00시` tick에서만 날짜를 함께 표시한다. 예: `6/8\n00시`
- 시간별의 나머지 tick은 시간만 표시한다. 예: `03시`, `06시`, `12시`

## 낚시기록

### 안내 팝업

낚시기록 탭 진입 시 안내 팝업을 표시한다.

문구 취지:

```text
낚시 기록은 워킹 루어 낚시나 보트 낚시처럼 이동하며 포인트를 탐색하는 상황에 최적화되어 있습니다.
기록 중 이동 경로와 상태 변화를 저장하고, 사진으로 조과를 남겨 히스토리에서 다시 확인할 수 있습니다.
```

기능:

- 최초 진입 또는 저장값이 꺼져 있을 때 표시한다.
- "다시 보지 않기"를 제공한다.
- 저장 키는 `hideFishingRecordGuidePopup`이다.

### 시작/종료 마커

리소스:

```text
ic_map_marker_start
ic_map_marker_end
```

동작:

- 기록 시작 후 유효한 GPS 좌표가 잡히면 시작 마커를 표시한다.
- 낚시기록 화면에서는 시작 마커만 표시한다.
- 종료 마커는 낚시기록 화면에서 따라다니거나 노출되지 않는다.
- 기록 종료 후 경로와 임시 마커 상태는 초기화한다.
- 히스토리 상세 화면에서는 시작/종료 마커를 모두 표시한다.
- 시작/종료 마커는 원형이므로 지도 marker anchor는 중앙 `(0.5f, 0.5f)`이다.
- 기존 낚시중/탐색중 pin 마커는 하단 기준 anchor `(0.5f, 1.0f)`를 유지한다.

### 상태 전환 마커

상태 마커는 아래 전환에서만 생성한다.

```text
이동중 -> 탐색중
이동중 -> 낚시중
```

생성하지 않는 경우:

- 시작 직후 첫 상태가 탐색중/낚시중인 경우
- 탐색중/낚시중 사이 전환
- 탐색/낚시에서 이동중으로 바뀌는 경우

## 히스토리 상세

### 시작/종료 마커

- 시작 마커는 세션 첫 record에서 파생한다.
- 종료 마커는 세션 마지막 record에서 파생한다.
- Google/Kakao 히스토리 지도 모두 시작/종료 마커에 클릭 id를 연결한다.
- 시작/종료 마커 탭 시 기존 낚시/탐색 상태 마커와 같은 하단 UI를 표시한다.
- 시작 제목은 `낚시 시작`이다.
- 종료 제목은 `낚시종료`이다.
- 사진 썸네일은 표시하지 않는다.

### 지점 수 계산

목록과 상세의 지점 수 계산 기준은 같아야 한다.

```text
시작 마커 1
+ 종료 마커 1, 단 record가 2개 이상일 때
+ 이동중 -> 탐색/낚시 상태 마커 개수
+ 사진 마커 개수
```

첫 시작 record는 상태 전환 카운트에서 제외한다.

### 상단 UI와 사진 뷰어

- 히스토리 상단 정보 카드는 accordion 방식으로 확장/축소한다.
- 뒤로 버튼, 날짜/시간, 삭제 버튼 영역은 고정한다.
- 상세 영역만 height animation으로 확장/축소한다.
- 조과 사진이 없으면 사진 섹션 구분선을 숨긴다.
- 사진 확대 뷰어의 하단 페이지 컨트롤은 navigation bar safe area와 최소 하단 여백을 반영한다.

## 빌드와 검증

주요 명령:

```bash
./gradlew assemblePublicDebug
./gradlew assembleInternalDebug
```

최근 검증:

- `./gradlew assemblePublicDebug` 성공
- `./gradlew assembleInternalDebug` 성공

수동 확인 포인트:

- 공개 빌드에서 현재수온 OpenAPI 화면이 뜨는지 확인
- 공개 빌드에서 수온분석 탭이 준비중 화면인지 확인
- 공개 빌드에서 `/api/regions` 호출이 발생하지 않는지 확인
- 내부 빌드에서 crawling/직접 서버 호출 화면이 뜨는지 확인
- 내부 빌드에서 앱 시작 시 `/api/regions` 호출이 유지되는지 확인
- 내부 수온분석 상세에서 날짜별/12시간/6시간/3시간 드롭다운과 가로 스크롤 확인
- 기록 시작 즉시 시작 마커가 보이는지 확인
- 기록 중 종료 마커가 현재 위치를 따라다니지 않는지 확인
- 기록 종료 후 경로와 임시 마커가 초기화되는지 확인
- 히스토리에서 시작/종료 마커 탭 시 하단 UI가 뜨는지 확인
- 히스토리 사진 확대 화면 하단 컨트롤이 소프트키 영역과 겹치지 않는지 확인
